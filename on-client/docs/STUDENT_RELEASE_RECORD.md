## 원문·실행 계약 대조

- `on-client/package.json`은 Node.js `24.19.0`을 요구하며 `start`는 `node src/server.mjs`입니다. 프로젝트 패키지 버전은 `0.2.11`입니다.
- 새 재현 환경에서 보고된 Node.js `v24.21.0`과 npm `11.19.0`은 실제 설치 버전이며, 프로젝트가 요구하는 Node.js 버전과 구분합니다.
- 사용자가 보고한 새 폴더의 `npm.cmd run check`는 통과했습니다. 이는 보고된 해당 명령의 결과이며, 이 문서 작성자가 다시 실행한 것은 아닙니다.
- 새 폴더에서 `npm.cmd start` 및 종료 후 재실행이 성공했다고 보고되었습니다. 콘솔 시작 메시지는 `케셰브 연결 확인: http://127.0.0.1:5189`였고 Chrome에서 `http://127.0.0.1:5189/`의 보호 현황 화면 표시를 확인했다고 합니다.
- `renderIdentity`, `renderStatus`, `renderAiConnection`의 학생 화면 표시와 `renderVulnerabilities`의 `조회 전(idle)` 화면 표시를 확인했다고 보고되었습니다. 이는 해당 화면 표시 확인이지 모든 상태·기능의 검증은 아닙니다.
- 실행 환경에서 `ENGINE_NOT_CONNECTED`가 확인되었습니다. 따라서 기존 서버·에이전트 연결은 성공하지 않았습니다. 로컬 앱 서버 시작은 접근 제어·XDR·AI 게이트웨이·OSV 또는 실제 조치 시스템 연결 성공을 의미하지 않습니다.
- 사용자는 `Ctrl+C` 후 종료 확인 질문에 `Y`를 입력해 PowerShell 프롬프트로 돌아온 것을 확인했다고 보고했습니다.
- 문서상 `package.json`에는 별도 `dependencies`가 선언되어 있지 않습니다. 이 기록은 `npm install` 또는 `npm ci`를 실행했다고 주장하지 않습니다. 새 환경에서 설치를 추가로 수행하지 않았다는 사실도 실행 진술 범위를 넘어서 단정하지 않습니다.
- 실제 연결·권한 설정을 원본 프로젝트에서 새 폴더로 무작정 복사하지 않습니다. 개인 설정 파일과 인증값은 Git, 이 문서, 제출 자료에 넣지 않습니다.

- 원본에서 작업할 때는 `git status --short`로 기존 변경을 확인하고, 기존 미커밋 작업의 파일과 내용을 보존합니다. 이 재현 기록은 사용자가 보고한 별도 clone/checkout을 기록하며 원본을 대체하지 않습니다.
- 검증이 실패해도 원본에 되돌리기·초기화·체리픽을 하지 않습니다. 재현 폴더를 보존하고 필요하면 지정 커밋으로 별도 폴더를 다시 만듭니다. 원래 작업으로 복귀할 때는 원래 프로젝트 폴더를 사용합니다.
- 앱이 실제 사용자 데이터나 별도 저장소를 생성·수정하는지, 그 데이터의 위치·백업·복원 방법은 이번 재현으로 확인되지 않았습니다. 로컬 상태가 자동 보존되거나 clone만으로 복원된다고 주장하지 않습니다. 실제 지속 데이터가 확인되면 담당 문서에 지정된 백업·복원 방법만 사용하고 개인 데이터나 인증 파일을 무단 복사하지 않습니다.
- 인증 설정은 재현 대상 소스와 별도로 취급합니다. 원본의 인증·개인 설정 파일을 새 폴더로 무작정 복사하지 않으며, 공개 커밋이나 로그에 비밀값을 넣지 않습니다.
