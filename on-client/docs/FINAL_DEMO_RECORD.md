## 1. 프로젝트 개요와 핵심 기능

PICASOAR는 보안 Agent 시작 틀에 Windows 로컬 PC 관제와 학생 화면을 추가한 프로젝트다. 미드나잇 선셋 2.0 테마와 리본형 P 로고를 사용한다. 제공 공통 UI와 학생 구현 영역은 구분한다.

| 핵심 기능 | 구현 범위 | 현재 확인 범위 |
|---|---|---|
| PC 자원 실측 | CPU, 물리 메모리, 시스템 디스크와 측정 시각 표시 | 기존 5일차 문서에 사용자 확인 기록이 있음 |
| Windows 연결·기록 조회 | 네트워크 어댑터, 방화벽 프로필, 최근 24시간 System/Application 경고·오류 건수 | 사용자 확인 기록이 있음. 공격·침해 판정 기능은 아님 |
| 보호 현황과 보안 정보 화면 | 핵심 기능 바로가기, 재조회·실패 안내, 업무 앱·보안 기록·계정·AI 연결 상태 표시 | 로컬 화면과 demo 예제 표시 확인 기록이 있음. 실제 SDP·XDR·AI 연동은 미완료 |

## 3. 7일차 시연 순서와 실행 명령

아래는 **앞으로 실행할 시연 절차**다. 이 절차를 문서에 적었다는 사실은 실행·통과 증거가 아니다. 기존 서버가 실행 중이면 중복 실행하지 않으며 다른 프로세스를 강제 종료하지 않는다.

### 3-1. 위치·버전·문법 확인

```powershell
Set-Location 'C:\Users\User\AppData\Local\ALEPH\Workbench\projects\PICASOAR'
Get-Location
git rev-parse HEAD
git status --short
Set-Location .\on-client
node --version
npm.cmd --version
npm.cmd run check
```

`npm.cmd run check`는 `node --check student/extension.mjs`만 수행한다. 브라우저 동작, 전체 서버 문법, 실측 정확도, 외부 연결 또는 공식 통과를 확인하는 검사가 아니다.

### 3-2. 기본 실행: Windows 실측과 미연결 상태

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

이것을 기본 실행 명령으로 사용한다. `-ExecutionPolicy Bypass`는 이 PowerShell 실행에만 적용되는 공식 실행 안내의 옵션이며, 영구 실행 정책·방화벽·Defender 설정을 변경하지 않는다. 이 문서 작성 과정에서는 실행하지 않았다.

1. 브라우저에서 `http://127.0.0.1:5189/`를 연다.
2. 보호 현황에서 CPU·메모리·시스템 디스크의 출처와 측정 시각을 보여 준다. 실패한 항목은 그대로 `확인 불가`로 설명한다.
3. 연결과 기록에서 네트워크·방화벽·최근 24시간 이벤트 범위를 보여 준다.
4. 두 다시 조회 버튼과 키보드 `Tab`·`Enter` 조작을 확인하고 결과를 기록한다.
5. 업무 앱·보안 기록·기기·세션 및 계정·AI 영역의 미연결 오류를 보여 준다. 오류를 성공 상태로 바꾸거나 숨기지 않는다.
6. 필요하면 도움정보를 조회해 공개 오류 코드만 확인한다. 키·토큰·개인 설정은 캡처하지 않는다.
7. 실행 창에서 `Ctrl+C`로 종료한다. 종료 확인 질문이 나오면 `Y`를 입력한다. 프롬프트 복귀와 종료 여부를 확인한다.

현재 0.2.11 실행기는 Native 설정을 자동으로 준비하지 않는다. 이 기본 명령에는 Native·SDP 설정이 없으므로 실제 연결이 활성화됐다고 가정하지 않는다. 설정 발급·로그인·앱 승인·실제 연결은 담당자 절차에 따라 별도로 확인한다.

### 3-3. demo 실행: 예제 판정과 이벤트

기본 서버의 종료를 확인한 후 같은 `on-client` 폴더에서 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
```

1. 같은 브라우저 주소에서 demo 표시를 확인한다.
2. 업무 앱의 개발 저장소(`repository`) 요청에 따른 예제 `deny` 판정과 보안 기록의 예제 `event-01`을 보여 준다.
3. 이 판정·이벤트는 실제 접근 차단이나 실제 XDR 탐지가 아님을 설명한다.
4. 같은 화면의 Windows PC 카드는 별도 로컬 조회이며 예제 숫자가 아님을 설명한다. 실패·확인 불가 항목도 구분한다.
5. 시연 후 종료한다. 필요하면 기본 명령으로 다시 실행하고 모드 변경 여부를 기록한다.

기존 문서에는 demo 화면 확인 기록이 있지만, `start-alekov.ps1 -Demo`라는 실행 경로 자체의 성공은 이번 작성에서 재검증하지 않았다.

## 5. 실제 외부 연동 미완료와 오류 코드

다음 오류는 사용자 보고와 앞선 읽기 전용 코드 분석을 근거로 기록한다. 이번 문서 작성에서 API 응답을 새로 수집하거나 복구를 시험하지 않았다.

| 코드 | 확인한 의미·발생 경로 | 현재 상태 |
|---|---|---|
| `ENGINE_NOT_CONNECTED` | 엔진 어댑터·메서드 미구성 또는 SDP 설정·통신 검증 실패 경로. 업무 앱·기기·세션·보안 기록 조회 실패로 보고됨 | 실제 SDP·XDR 조회 성공 미확인 |
| `NATIVE_HOST_DISABLED` | 서버에 Native host context가 없는 상태의 계정 연결 요청 | 계정 연결 비활성화 보고. 정상 설정 준비와 로그인 확인 필요 |
| `ALEKOV_CONNECT_UNAVAILABLE` | AI 연결 관리자 활성화에 필요한 구성 미충족 등의 경로 | AI 계정 연결 불가 보고. 단순 UI 수정으로 승인 권한을 만들 수 없음 |
| `AI_REQUEST_UNVERIFIED` | 프런트엔드가 알 수 없는 오류 또는 검증하지 못한 결과에 사용하는 공통 오류 | 원본 API 코드·응답 확인 필요. 실제 모델 응답 실패로 단정하지 않음 |

서버 시작·HTTP 200·예제 표시·어댑터 구성 표시만으로 실연결 성공을 판단하지 않는다. 실제 사용자 범위의 조회, 현재 권한으로 검증된 AI 모델 점검과 사건 근거에 결속된 설명 결과가 각각 필요하다. 실제 보안 조치 집행과 효과 관측, OSV 실제 조회 성공도 이 문서에서 확인했다고 주장하지 않는다.

## 6. 6일차 공식 포장과 제출 가능 여부

**6일차 공식 `package-app` 포장은 미완료다.**

- 현재 0.2.11 `package.json`에는 `package-app` 스크립트가 없고 해당 공식 포장 도구도 현재 앱 폴더에 없다.
- Downloads의 공식 0.2.21 ZIP과 업데이트 도구는 존재한다. 앞선 읽기 전용 분석에서 ZIP SHA-256이 로컬 업데이트 도구의 고정값과 일치함을 확인했다. 이는 포장·설치·실행 성공 증거가 아니다.
- 자동 업데이트는 수정된 제공 파일을 보존하기 위해 `UPDATE_FILE_MODIFIED`로 중단됐다. 원본 파일을 강제 원복·덮어쓰기하지 않았다.
- 별도 환경 검사에서 `PROVIDED_RUNTIME_NOT_INSTALLED`가 보고됐다. 앞선 분석에서도 현재 사용자 홈의 고정 승인 런타임 폴더가 없음을 확인했다. 공식 전체 앱 포장에는 담당자의 승인 실행 환경이 필요하다.
- 별도 공식 0.2.21 도구가 현재 소스를 읽는 경로는 코드상 검토했지만 실제 포장·설치·바로가기 실행은 수행하지 않았다. 우회 옵션이나 임의 승인 파일은 사용하지 않았다.

**공식 안내에서 구형 시작 틀의 포장 생략을 허용한다는 사용자 확인 사항을 반영한다. 따라서 포장 미완료만으로 최종 제출 불가라고 단정하지 않는다.** 해당 생략 허용 안내의 원문·적용 조건은 이번 작성에서 직접 열람하지 않았으므로, 제출 시 최신 공식 안내에서 본인에게 적용되는지 확인해야 한다.

현재 기록은 문서 준비 상태이며 공식 제출·통과를 인증하지 않는다. 포장 생략 허용과 별개로 제출 대상 단계·원문·커밋 일치 등 공식 요건은 확인해야 한다. 커밋과 Push는 별도 승인 전까지 하지 않는다.

문서 작성 후에는 `git diff --check`와 문서 내용·변경 범위를 검사한다. 최종 검사 결과는 작성 완료 보고에 남긴다. 새 실행 화면은 아직 수집하지 않았다. 시연 때 실제 화면·모드·조회 시각·성공 또는 오류를 기록하고 인증 정보는 제외한다.

## 8. 재현 방법과 제한사항

- 현재 작업 경로의 시연은 3장의 명령을 사용한다. 검증 당시 HEAD·작업 상태·환경·시각을 함께 기록한다.
- 별도 폴더의 5일차 재현은 [기존 실행 안내](STUDENT_LAUNCH_GUIDE.md)의 부록 A를 따른다. 해당 과거 커밋에는 이후 로고·문서가 모두 포함됐다고 가정하지 않는다.
- 새 최종 커밋 재현은 별도 승인으로 커밋이 생성된 뒤, 원본과 겹치지 않는 새 폴더에서 정확한 제출 해시를 확인하고 진행한다. 이 문서 작성 중에는 clone·checkout·커밋·Push를 하지 않는다.
- 개인 Native·SDP 설정과 키·토큰·인증서·vault·registry는 소스 재현과 별개다. 백업이나 다른 프로젝트에서 무단 복사하지 않는다.
- 실패 상황 자동화 검사, 다른 PC·독립된 제3자의 재현, 실제 SDP·XDR·AI·OSV 연결, 실제 보안 조치 효과, 공식 포장·설치·최종 제출 결과는 미확인 또는 미완료다.
- 기존 소스·학생 파일·백업·기존 미커밋 작업은 보존한다. 이 작업의 변경 범위는 이 문서 신규 작성과 README 링크 한 줄뿐이다.

시연 시 다음 양식을 실제 결과로 채운다. 빈 항목은 성공으로 처리하지 않는다.
